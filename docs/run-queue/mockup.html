Running, the queue, and kept results

A made-up project, run by a pretend queue (seconds here stand for minutes). Each node that does work has a state dot before its name (a turning ring while it is queued or working; hover it for what it is doing) and a ▶ in its top right corner to run it and everything it needs. The queue lists every job in the order asked. What is worked out is kept in cache\, so it is not worked out twice. Plan: docs/run-queue/plan.md.

What to look at

  • ▶ on the Audio match queues the link's SOURCER, the file's SOURCER, then the Cut detector, then the match. Each waits for what it needs and says what that is. The Timeline after it is not a job.
  • The link downloads with a turn of its own (2 at once), then waits for a turn to decode, shared with every heavy job (2 here, half the cores in the program).
  • The Cut detector's threshold only changes what is shown: nothing runs again. Its picture scale changes what it works out: it turns stale, and so does the Audio match after it. With Auto on they run again, the SOURCERs stay kept.
  • Replace the file in the second SOURCER: its key changes, and everything that reads it is stale.
  • Open the project again: whatever is kept loads at once (teal), nothing decodes.
  • Play on the link's SOURCER with no sound yet: Play queues its decode and waits for it.
  • The microphone is live: Run starts it and the ENF node reading it, both pulse until Stop. A live result is never kept.
